# Бизнес-домен: API маркетплейса для маршрутизации заказов по распределительным центрам

Рассматривается API маркетплейса, принимающее заказы покупателей из веб- или мобильного приложения и маршрутизирующее их к доступным распределительным центрам для комплектации и отправки. Если все центры заняты, заказ ожидает в общей ограниченной очереди маршрутизации на стороне API-шлюза.
Источники считаются бесконечными: после одного заказа каждый источник продолжает генерировать следующие. Интервалы поступления равномерны (`ИЗ2`). Каждый распределительный центр может одновременно обрабатывать только один заказ; время обслуживания распределено экспоненциально (`ПЗ1`).

# 1. ЭЛЕМЕНТЫ БИЗНЕС-ДОМЕНА
## 1.1. Источник (ИБ, ИЗ2).
 Источниками являются покупатели маркетплейса, оформляющие заказы через сайт или мобильное приложение и обращающиеся к API. Источник считается бесконечным: после оформления одного заказа покупатель может формировать новые запросы в течение всего времени работы системы. Поступление заказов соответствует ИЗ2 — равномерному закону, то есть заказы появляются через случайные интервалы времени, равномерно распределённые в заданном диапазоне.
## 1.2. Буфер (Д10З2). 
Буфером является очередь маршрутизации в API-шлюзе — заказы, ожидающие назначения на распределительный центр. Если все распределительные центры заняты, заказ встаёт на первое свободное место в очереди, начиная с начала, при освобождении места N все заказы, стоящие после него, сдвигаются на одну позицию вперёд. Каждый новый заказ встаёт в конец очереди.
## 1.3. Прибор (ПЗ1). 
Приборами являются распределительные центры, комплектующие и отправляющие заказ. Каждый центр в один момент времени обрабатывает один заказ. Время обработки задаётся экспоненциальным законом ПЗ1.

## 1.4. Дисциплина отказа (Д1ОО4)
При полном заполнении очереди маршрутизации вновь поступивший заказ вытесняет из буфера последнюю заявку, уже находящуюся в очереди, то есть заявку, которая поступила туда позже остальных и ожидает меньше времени. Вытесненная заявка удаляется из буфера и учитывается как отказ, а новая заявка занимает освободившееся место. Остальные заявки, находящиеся в очереди, не затрагиваются и продолжают ожидать назначения на распределительные центры в прежнем порядке.
Таким образом, при переполнении очереди новый заказ принимается, а отказ фиксируется для последней заявки, ранее помещённой в буфер. Это соответствует дисциплине Д1ОО4 — «последняя поступившая в буфер».
## 1.5. Дисциплины постановки на обслуживание (Д2П2, Д2Б4). 
Из очереди маршрутизации заказы выбираются по Д2Б4: приоритет определяется источником, например, заказы от Premium-покупателей обслуживаются раньше заказов обычных покупателей, выбор происходит по одному заказу за раз. При равном приоритете нескольких заказов выбирается тот, что ждёт дольше остальных — это зеркалит дисциплину отказа: раз при переполнении отклоняются именно новые заказы, справедливо в первую очередь маршрутизировать самый давний. При наличии нескольких свободных распределительных центров действует Д2П2 — выбор по кольцу: поиск свободного центра каждый раз начинается с указателя на позицию последнего задействованного центра.
## 1.6. Заявка.
Заявкой является один заказ покупателя маркетплейса, содержащий состав корзины, номер источника и время поступления. Для моделирования учитываются момент поступления заказа, время ожидания в очереди маршрутизации, начало и окончание обработки распределительным центром. После успешной обработки заказ покидает систему.
## 1.7. Отображение работы модели (ОР1, ОД2). 
В пошаговом режиме используется ОД2: отображается формализованная схема модели и текущее состояние: занятость распределительных центров, заполненность очереди маршрутизации, положение указателя. После завершения моделирования применяется ОР1 — сводная таблица результатов: процент отклонённых заказов, среднее время пребывания заказа в системе, загрузка распределительных центров, без построения графиков.
