# Правила модели и контракт взаимодействия компонентов

## 1. Состав СМО

- **Источник** — бесконечный поток заявок покупателя/класса покупателей маркетплейса.
- **Заявка** — заказ с ID, ID источника, временем генерации, временем начала и окончания обслуживания, состоянием.
- **Буфер** — общий ограниченный FIFO-контейнер очереди маршрутизации.
- **Диспетчер постановки** — работает с буфером и политикой переполнения. Он не выбирает распределительный центр и не проверяет занятость приборов.
- **Диспетчер выбора** — реагирует на принятую в очередь заявку или освобождение центра; выбирает одну заявку по `Д2Б4`, а затем свободный центр по `Д2П2`.
- **Распределительный центр** — прибор, который обслуживает один заказ за раз.
- **Календарь событий** — упорядочивает моменты генерации заявок и завершения обслуживания.
- **Сборщик статистики** — считает генерацию, вытеснения/отказы, ожидание, время в системе, обслуживание и занятость каждого центра.

## 2. Закон генерации и обслуживания

Для каждого источника следующий интервал между генерациями `Δt` берётся из равномерного распределения `U(Tmin, Tmax)` (`ИЗ2`):

`T_next = T_current + U(Tmin, Tmax)`.

Для обработки заявки центром время обслуживания выбирается по экспоненциальному закону `ПЗ1`. В конфигурации нужно явно определить, задаётся ли среднее время `E[Tservice]` или интенсивность `μ`; в используемой нотации `Tservice ~ Exp(μ)` означает параметр интенсивности `μ`, следовательно `E[Tservice] = 1/μ`.

## 3. Постановка в буфер (`Д1ОЗ2`)

1. Диспетчер постановки получает `OrderGenerated`.
2. Если есть свободное место — добавить заявку в хвост общей очереди.
3. Если удаляется элемент из буфера, последующие элементы логически сдвигаются к началу очереди. Новая заявка при нормальной постановке всегда занимает хвост.
4. Диспетчер постановки возвращает результат операции и не обращается к пулу приборов.

## 4. Переполнение очереди

При полном буфере выполняется следующая последовательность:

1. При полном буфере получить последнюю ожидающую заявку.
2. Удалить её из буфера и зарегистрировать вытеснение/отказ для источника этой заявки.
3. Поместить вновь поступившую заявку в освобождённое последнее место; новая заявка принята.
4. Очередь сохраняет порядок оставшихся заявок; ранее стоявшие заявки (кроме вытесненной последней) не затрагиваются.

Новая заявка принимается, а отказ регистрируется для вытесненной последней заявки буфера.

## 5. Выбор заявки и центра (`Д2Б4`, `Д2П2`)

1. Диспетчер выбора срабатывает по `OrderAccepted` и `DeviceReleased`.
2. Пока в буфере есть ожидающие заявки и найден свободный центр, диспетчер назначает по одной заявке.
3. `Д2Б4`: из всех ожидающих выбирается заявка источника с наивысшим приоритетом, определяемым номером/приоритетом источника. При одинаковом приоритете применяется FIFO (минимальное время поступления) как явное правило разрешения ничьей для данного домена.
4. `Д2П2`: свободный центр ищется по кольцу, начиная с текущего указателя. После назначения указатель сдвигается на следующую позицию после выбранного центра и продолжает циклически обходить пул.
5. Сначала следует удостовериться, что свободный прибор существует; только потом удалять заявку из буфера. Если все приборы заняты, заявка остаётся ждать в буфере.
6. Центр начинает обслуживание заявки и планирует `ServiceCompleted` на время `now + Tservice`.
7. При завершении обслуживания центр освобождается, статистика обновляется, а событие `DeviceReleased` повторно запускает диспетчер выбора.

## 6. Триггеры, состояния и статистика

Основные триггеры дискретно-событийной модели:

- `OrderGenerated(sourceId, time)` — новая заявка.
- `OrderAccepted(orderId, time)` — диспетчер постановки завершил постановку в очередь.
- `ServiceCompleted(deviceId, orderId, time)` — закончено обслуживание.
- `DeviceReleased(deviceId, time)` — центр доступен для следующей заявки.
- `SimulationEnd` — генерация остановлена; сбор статистики завершается только после выхода из системы последней обслуживаемой заявки и опустошения буфера.

Сборщик статистики должен учитывать каждую сгенерированную заявку, включая вытесненные/отклонённые. Минимальные счётчики и показатели:

- число сгенерированных заявок на источник;
- количество и вероятность вытеснения/отказа на источник;
- среднее ожидание в буфере;
- среднее обслуживание;
- среднее время в системе;
- дисперсии времени ожидания и обслуживания;
- коэффициент использования каждого центра `busyTime / totalSimulationTime`.

В автоматическом режиме применяется `ОР1` (сводная таблица); в пошаговом — `ОД2` (формализованная схема и текущее состояние). Временная диаграмма не строится.
